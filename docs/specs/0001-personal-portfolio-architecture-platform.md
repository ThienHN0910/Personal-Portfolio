# Specification: Personal Portfolio & Architecture Platform

## Problem Statement

Technical leaders, hiring managers, and prospective clients visiting developer portfolios often face generic, uninspired templates with clunky animations, sluggish loading times, and shallow project summaries that fail to demonstrate senior-level engineering rigor and system design depth. Additionally, portfolio owners frequently miss timely business opportunities due to delayed or siloed inbound contact alerts, while client-side single-page applications struggle to provide search engine and social media crawlers with rich dynamic previews without expensive and complex SSR infrastructure.

## Solution

A high-performance, editorial-grade portfolio and technical publishing platform engineered with Vue 3, TypeScript, GSAP, and Lenis smooth scrolling. The platform features an avant-garde broken-grid layout, deep obsidian dark mode typography, luxury CKEditor rich-content rendering, and a multi-channel inbound pipeline with instant Telegram Bot notifications. A build-time static snapshot prerendering system delivers edge-cached, crawler-ready OpenGraph previews with zero server runtime overhead.

## User Stories

1. As a prospective client or engineering recruiter, I want to experience smooth, physics-based scrolling and tactile micro-interactions, so that I can immediately perceive the engineer's frontend craftsmanship.
2. As a design director, I want to view high-contrast editorial typography and an asymmetric bento grid layout, so that the presentation feels distinct from generic AI-generated templates.
3. As a technical hiring manager, I want to explore detailed Case Studies with system specifications, architecture breakdowns, and tech matrices, so that I can evaluate the engineer's depth in real-world software design.
4. As a developer browsing technical content, I want to read long-form Articles formatted with styled code blocks, luxury pull-quotes, data matrices, and media embeds, so that I can absorb complex technical explanations cleanly.
5. As a mobile reader, I want a real-time reading progress bar pinned to the top of long-form Articles, so that I have a clear sense of reading depth and remaining content.
6. As a portfolio visitor, I want to filter and search Case Studies and Articles by categories and keywords in real time, so that I can quickly find relevant domains of interest.
7. As a prospective collaborator, I want to submit an inquiry through a secure contact form protected by Cloudflare Turnstile CAPTCHA, so that my message reaches the engineer reliably without dealing with spam friction.
8. As the portfolio owner, I want to receive an instant, formatted push notification on Telegram whenever a new inquiry is submitted, so that I can respond to opportunities within minutes.
9. As the portfolio owner, I want all visitor inquiries to be persisted securely in MongoDB, so that no messages are lost even if an external notification channel experiences downtime.
10. As a social media user sharing a Case Study or Article link on LinkedIn, X, or Facebook, I want the link to render a rich preview card with title, excerpt, and cover image, so that shared links look professional.
11. As a search engine crawler, I want to discover a fully populated `sitemap.xml`, `robots.txt`, and prerendered static HTML snapshots of all dynamic routes, so that all publications are indexed accurately.
12. As the portfolio owner, I want an administrative dashboard authenticated via stateless JWT to create, edit, delete, and organize Case Studies and Articles, so that content management remains frictionless.
13. As the portfolio owner, I want media assets uploaded via the admin panel to be stored on Cloudinary with automatic WebP/AVIF format and quality negotiation, so that page load times remain lightning-fast worldwide.
14. As a keyboard-only or assistive technology user, I want full keyboard accessibility, visible focus states, and a skip-to-content mechanism, so that I can navigate the entire platform comfortably.

## Implementation Decisions

- **Domain Language Alignment**: All terminology adheres strictly to the canonical definitions in `CONTEXT.md` (`Case Study`, `Article`, `Publication`, `Skill Matrix`, `Work Chronology`, `System Spec Rail`, `Rich Content`, `Snapshot Prerender`).
- **Client Runtime Sanitization (ADR-0001)**: The database stores semantic source HTML generated by CKEditor, while `sanitizeRichContent()` executes client-side normalization (transforming `oembed` tags to responsive iframes) and strict `DOMPurify` sanitization before injecting into the DOM via `v-html`.
- **Static Snapshot Prerendering for SEO (ADR-0002)**: Build scripts (`generate-seo-files.mjs` and `prerender-social-pages.mjs`) fetch dynamic route data during `npm run build` and output static HTML files containing server-rendered `<meta>` and OpenGraph tags to `dist/`, eliminating the need for Node.js SSR runtime servers.
- **Stateless JWT Bearer Authentication (ADR-0003)**: Administrative sessions use stateless JSON Web Tokens stored in `localStorage` and sent via `Authorization: Bearer <token>` HTTP request headers to decouple frontend and backend across separate Vercel deployment origins without cross-site cookie restrictions.
- **Cloudinary Asset Optimization (ADR-0004)**: Image assets are uploaded through the backend to Cloudinary and delivered with automatic format and compression negotiation (`f_auto,q_auto`).
- **Multi-Channel Contact Notification (ADR-0005)**: Contact form submissions execute Cloudflare Turnstile verification, save the record to MongoDB, and trigger an asynchronous, non-blocking Telegram Bot API dispatch (`sendMessage` with Markdown formatting) to the owner's Telegram Chat ID.
- **Aesthetic Calibration**: Global design dials are locked at `DESIGN_VARIANCE: 8` (asymmetric broken grid), `MOTION_INTENSITY: 8` (GSAP split-line reveals, magnetic cursor pull, Lenis inertia scroll), and `VISUAL_DENSITY: 3` (expansive negative space).

## Testing Decisions

- **Testing Principles**: Tests must verify observable external behavior and contracts rather than internal implementation details.
- **Seam 1: HTTP API & Inbound Notification Boundary (Highest Seam)**:
  - Verify that `POST /api/contact` rejects payloads without Turnstile response or valid fields.
  - Verify that successful submissions insert into MongoDB and trigger the Telegram notification dispatch payload.
  - Verify that `GET /api/projects` and `GET /api/blog` return correctly paginated and filtered data.
- **Seam 2: Client Rich Content Sanitization Boundary**:
  - Verify that `sanitizeRichContent()` strips malicious `<script>` tags, event handlers (`onload`, `onerror`), and untrusted iframe sources while correctly expanding valid YouTube/Vimeo `oembed` tags.
- **Seam 3: Build & SEO Snapshot Pipeline**:
  - Verify that `npm run build` generates valid `sitemap.xml`, `robots.txt`, and static HTML files in `dist/` with valid `<meta property="og:title">` tags for every dynamic slug.

## Out of Scope

- Real-time live comments or public user registration on Articles.
- Direct e-commerce, payment gateway integrations, or paid subscription walls.
- Native mobile application builds (iOS/Android wrappers).
- Full Node.js runtime SSR server deployment (Nuxt 3 migration).

## Further Notes

- The Telegram notification service operates asynchronously and non-blockingly, ensuring that temporary Telegram API latency or network interruptions do not delay the HTTP response to visitors submitting inquiries.
- All animations strictly modify `transform` and `opacity` properties to guarantee consistent 60fps rendering without triggering browser layout reflows.
