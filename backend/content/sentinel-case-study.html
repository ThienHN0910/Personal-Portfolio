Sentinel is a Discord community bot with a public, live-data dashboard and games that span Discord and the web. It records activity observed after installation, supports server-level voice settings, and gives members and moderators a clear view of chat, voice, and level statistics.

The product problem

A community's activity is distributed across messages, voice channels, and transient Discord interactions. Server owners need a way to inspect that activity without mistaking a screenshot or fabricated demo for their own data. Sentinel makes the dashboard read the same bot-owned data that powers its commands. The public views show observed totals; management settings require a Discord login and a fresh permission check.

System architecture

The Discord Gateway feeds a Node.js bot. A Fastify API on the same service exposes health, dashboard, ranking, game, and administration routes. MongoDB stores statistics, configuration, sessions, reminders, and game state. A Vue 3 frontend deployed separately calls that API over HTTPS. The site can be opened anonymously for public statistics; authenticated actions go through Discord OAuth2 and server-side sessions.

Live activity with honest boundaries

The dashboard reads guild membership and voice presence alongside stored message and voice totals. Its heatmaps cover the recent seven-day window while ranking totals remain cumulative from when Sentinel began observing activity. An active voice session is labelled as an estimate until the session is settled. The complete ranking view pages through chat, voice, and level data, including users with historical records, so large guilds do not require one unbounded response.

A single game across two interfaces

Tic-tac-toe and rock-paper-scissors are light two-player games. A member can start in Discord or on the web and continue the same session on the other surface. The server stores the authoritative state; each move checks guild membership, actor identity, phase, expiry, and a version number. A stale move receives a conflict response instead of silently overwriting another player's action. Games are for fun and do not grant XP or coins.

Privacy, control, and operations

The web management view requires Discord OAuth2. The API stores an opaque session token as a hash and checks current Manage Server permission before reading or changing guild settings. OAuth access tokens are discarded after login. The bot stores activity counters and extracted word frequencies for analytics rather than a full copy of every message. Reminder messages are delivered privately by DM, with limits and expiration to keep the queue bounded.

The bot and API run on a VPS under PM2; the frontend runs on Vercel. Direct game URLs are handled as SPA routes, while the API health endpoint stays JSON. Automated tests cover state transitions, authorization, ranking queries, reminders, and frontend views. Human multi-account Discord play and DM delivery remain separate live checks.
