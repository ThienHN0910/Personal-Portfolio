ACVIS (Automated Code Vulnerability Identification System) is an enterprise-grade DevSecOps platform and university graduation capstone project developed at FPT University Da Nang (Fall 2026). It bridges the historic gap between high-noise static analysis (SAST) and risky dynamic exploitation by uniting in-process Tree-sitter AST taint propagation with safe, deterministic Non-Destructive Testing (NDT) exploit verification and Google Gemini AI remediation.

The capstone challenge: Eliminating the false-positive alert flood

Conventional Static Application Security Testing (SAST) tools rely heavily on regular expressions, flooding engineering teams with noisy alerts where up to 80% turn out to be harmless false positives. Conversely, traditional Dynamic Application Security Testing (DAST) scanners often run destructive payloads that can corrupt staging databases, trigger mass email dispatches, or crash mission-critical services.

ACVIS was architected to solve both sides of this dilemma. As the Lead Architect of a 5-engineer capstone team, I designed a multi-phase verification pipeline: candidate code flows flagged during static syntax analysis are automatically converted into safe, passive HTTP probes that execute against staging environments. Only findings with undeniable, ground-truth evidence are allowed to trip the GitHub PR merge gate.

5-Tier Enterprise DevSecOps architecture

ACVIS decouples code ingestion, static parsing, vector matching, polyglot persistence, and dynamic sandboxing into five distinct architectural tiers following Domain-Driven Design (DDD) and Clean Architecture principles:

Architectural Tier Technologies Core Responsibilities
Tier 1: Ingestion Gateway C# / ASP.NET Core, GitHub App, HMAC SHA-256 Processes code snippets, zip files, manual git repositories, and GitHub push webhooks. Manages .acvisignore rules and commit diff extractions.
Tier 2: Multi-Tier SAST Pipeline Tree-sitter C bindings, P/Invoke, Gemini AI Executes Shannon entropy secret scans, in-process Tree-sitter AST syntax parsing, intra-procedural taint tracking, 768-dim vector RAG, and AI fallback.
Tier 3: Polyglot Storage & Cache Supabase PostgreSQL, MongoDB Atlas, Upstash Redis PostgreSQL maintains ACID relational data across 15 tables. MongoDB stores AST nodes, 90-day TTL finding caches, and diff payloads. Redis L2 accelerates rules.
Tier 4: Dynamic Exploit Sandbox Python FastAPI, Vercel Serverless, SSRF Guard Runs deterministic Non-Destructive Testing (NDT) templates with an 8-second execution budget, DNS validation, and a standardized tri-state exit oracle.
Tier 5: Presentation & Delivery Vue 3, TypeScript, Pinia, Flutter Android Provides an editorial pearl-and-cobalt web dashboard, split/unified diff patch viewer, GitHub Check Run annotations, and mobile push alerts.

Intra-procedural data-flow taint analysis & Tree-sitter AST

To avoid the CPU and memory bloat of external command-line wrappers, ACVIS binds directly to Tree-sitter native C libraries via .NET 8 P/Invoke. The syntax parser inspects Abstract Syntax Trees for PHP and JavaScript/TypeScript in memory, discovering sources of untrusted input such as $_GET, $_POST, or request parameter objects.

The Data-Flow Taint Tracking Engine follows variables across intermediate assignments until they reach dangerous sinks such as database queries or file system calls. Crucially, per ADR-0026, when untrusted inputs pass through recognized sanitizer functions (such as parameterized PDO queries or casting helpers), the finding is automatically downgraded to Info / Sanitized rather than ringing alarm bells.

Safe dynamic verification & The Non-Destructive Testing (NDT) guarantee

Per ADR-0052, executing dynamic arbitrary Python scripts against staging systems was explicitly prohibited to ensure environment safety. Instead, ACVIS implements deterministic NDT templates for the top 5 high-impact CWEs:

CWE-89 SQL INJECTION

Employs multi-round Boolean differentials (AND 1=1 vs AND 1=2) and syntax error signature reflection. Probes never execute DROP, DELETE, or UPDATE.

CWE-22 PATH TRAVERSAL

Issues read-only file probes checking for known operating system landmarks (/etc/passwd or win.ini). Probes never write, overwrite, or delete remote files.

CWE-639 IDOR / BOLA

Performs 4-phase cross-tenant identity segregation checks strictly using read-only HTTP GET verbs, preventing unintended resource modification.

CWE-798 HARDCODED SECRETS

Executes active read-only dry-run authentication calls against provider APIs (GitHub, Slack). All tokens in output logs are strictly masked (***REDACTED***).

The sandbox communicates results through a standardized Tri-State Exit Code Oracle: Exit Code 0 (Confirmed Vulnerability) locks the PR merge gate; Exit Code 1 (Mitigated / Safe) confirms defense mechanisms hold; and Exit Code 2 (Inconclusive) logs network or configuration warnings without blocking engineering delivery.

Polyglot storage offloading & Cloud resilience

Operating an enterprise security system within free-tier cloud limits required ruthless persistence hygiene. In the initial implementation, storing multi-megabyte Git commit diffs in PostgreSQL caused rapid storage inflation, threatening Supabase's 500MB free tier ceiling due to TOAST table overhead.

Under ADR-0056, commit diff payloads were offloaded to MongoDB Atlas with an automated 30-day TTL expiration, reducing the average PostgreSQL row size in scan_jobs from ~5MB to just 180 bytes. Similarly, detailed vulnerability analysis documents in MongoDB's vuln_detail_cache expire after 90 days, guaranteeing stable database operations indefinitely without manual intervention.

Governance, community scoring & Rule lifecycle

Security detection rules evolve continuously. ACVIS features a collaborative Dataset Proposal workflow where community contributors can author new detection patterns. To ensure consensus integrity without heavy table joins, the net consensus value is materialized as an indexed CommunityScore column in PostgreSQL, updated atomically. Once a proposal is approved or rejected, a strict Voting Lock (ADR-0031) freezes all community reactions, and a background vectorization worker computes 768-dimensional embeddings to immediately enhance scanning for all platform tenants.
