1. In-Process Tree-Sitter AST Parsing & Data-Flow Taint Tracking

Traditional regex-based scanners cannot comprehend syntactic hierarchy or execution scopes. Running external command-line tools for every file scanned in a multi-project repository introduces prohibitive process-spawn overhead. To deliver sub-second static analysis, ACVIS communicates directly with Tree-sitter native C libraries via .NET 8 P/Invoke bindings (TreeSitterPhpParserService.cs).

The static engine navigates the Abstract Syntax Tree in memory, identifying untrusted sources (e.g. $_GET, $_POST, request parameters) and tracking their movement across assignments, function arguments, and string concatenations until they reach potentially dangerous execution sinks (e.g. raw SQL queries, file read operations, or DOM outputs). 

// Intra-Procedural Data-Flow Taint Tracking with Sanitizer Downgrade (ADR-0026)
public ScanFinding EvaluateTaintPropagation(AstNode sourceNode, AstNode sinkNode, List<AstNode> intermediateNodes) {
    bool isSanitized = intermediateNodes.Any(node => _sanitizerCatalog.IsKnownSanitizer(node.FunctionName));
    
    if (isSanitized) {
        // Automatically downgrade to Informational rather than raising a critical blocker
        return new ScanFinding(Severity.Info, FindingStatus.Sanitized, "Untrusted input correctly sanitized before reaching sink.");
    }
    
    return new ScanFinding(Severity.High, FindingStatus.Unmitigated, "Direct untrusted data propagation from source to sink without sanitization.");
}

Under ADR-0026, when an untrusted input flow passes through recognized sanitizers (such as prepared PDO statement bindings, intval(), or htmlspecialchars()), ACVIS automatically downgrades the finding to Info / Sanitized. This single mechanism reduced false-positive flags in our evaluation benchmarks by over 65%.

2. 768-Dimensional Vector Embeddings & Tiered RAG Thresholds (ADR-0030 & ADR-0045)

ACVIS maintains an extensive security catalog of detection rules mapped to CWE, OWASP, and CVE standards in MongoDB Atlas (vulnerability_rules). Whenever a new rule is published or submitted through community governance, an asynchronous background worker (RuleVectorizationWorker) converts its syntactic signature, description, and remediation guidance into a 768-dimensional dense vector using Google Gemini embeddings.

Invoking large generative models for every line of code across large pull requests is cost-prohibitive, introduces severe latency, and quickly hits rate limits. To solve this, ACVIS implements a Tiered Vector Threshold Architecture:

< 0.75 Similarity

STANDARD PIPELINE

Below semantic confidence threshold. Bypasses RAG short-circuiting and routes through standard Tree-sitter AST taint tracking.

0.75 to 0.84

TOP-10 GUIDANCE

Moderate confidence. Retrieves the Top-10 most similar vulnerability rules from MongoDB to provide structured context for the AI scanner.

≥ 0.85 Similarity

SHORT-CIRCUIT PASS

High confidence match. Assigns the CWE and Rule ID immediately, bypassing redundant static steps, and feeds directly into exploit generation.

During webhook scans on multi-file commits, rapid burst queries easily triggered HTTP 429 quota exhaustion against the Gemini API. We resolved this by building an in-memory Channel Rate Pacer using .NET 8's System.Threading.Channels.Channel<GeminiWorkItem>. The worker enforces a minimum spacing of 4.2 seconds between requests (guaranteeing throughput stays under the 14 RPM ceiling) combined with exponential backoff and randomized jitter.

3. Non-Destructive Testing (NDT) Sandbox & Tri-State Exit Code Oracle

The most critical design decision in ACVIS was determining how to dynamically verify findings without damaging the target application. Per ADR-0052, executing dynamic Python scripts generated on the fly was strictly prohibited. Instead, the verification runner relies exclusively on deterministic NDT templates for the 5 supported CWE classes:

  • CWE-89 (SQL Injection): Multi-round Boolean differentials (AND 1=1 vs AND 1=2) and syntax error reflections. Zero destructive writes (no DROP, DELETE, INSERT, or UPDATE).
  • CWE-22 (Path Traversal): Read-only file probes checking for known operating system landmarks (/etc/passwd or win.ini). Never mutates or removes remote files.
  • CWE-639 (IDOR / BOLA): Cross-tenant identity checks strictly enforcing read-only HTTP GET requests across separated test identities.
  • CWE-798 (Hardcoded Secrets): Active read-only dry-run authentication against official identity provider APIs (GitHub, Slack) with full in-memory token masking (***REDACTED***).
  • CWE-79 (Cross-Site Scripting): Pure HTTP DOM reflection probe with Content-Security-Policy (CSP) evaluation. Serverless lack of headless browsers classifies reflection as Inconclusive to avoid false execution claims.

The verification sandbox reports outcomes through a standardized Tri-State Exit Code Oracle:

Oracle Exit Code Status Definition Impact on Pull Request Merge Gate
Exit Code 0 Confirmed Vulnerability Blocks Merge: Incontrovertible exploit indicator observed; fails GitHub Check Run.
Exit Code 1 Mitigated / Safe Passes: Target parameter responded correctly without triggering vulnerability indicator.
Exit Code 2 Inconclusive / Notice Passes (Notice Only): Staging unreachable, parameter missing, CSP active, or 8s budget expired.

4. Polyglot Persistence & Overcoming Free-Tier Cloud Limits (ADR-0056)

Operating a full-scale DevSecOps system within free-tier cloud constraints required surgical architecture choices. Supabase PostgreSQL provides 500MB of free storage. In early webhook testing, saving full Git commit diffs directly in the scan_jobs table quickly consumed tens of megabytes due to PostgreSQL's TOAST table overhead on large JSON/text payloads.

Under ADR-0056, we re-architected the storage layer into a polyglot model:

  • PostgreSQL (Supabase): Stores strictly structured relational entities (Users, Repositories, ScanJobs, ScanResults, WebhookDeliveries, Billing) across 15 tables with Code-First EF Core migrations.
  • MongoDB Atlas (M0): Offloads commit diff payloads (scan_job_diffs) with a 30-day TTL index, shrinking the PostgreSQL row size in scan_jobs from ~5MB down to ~180 bytes.
  • Granular Cache TTL: Vulnerability detail documents in vuln_detail_cache expire automatically after 90 days.
  • Upstash Redis L2: Caches frequently accessed policy rules and proposal scores to minimize MongoDB Atlas network roundtrips.

5. Closing the Loop: Automated Patches & Security Merge Gates

Detecting a vulnerability is insufficient; developers require actionable, copy-ready fixes. When a vulnerability is confirmed with Exit Code 0, ACVIS feeds Gemini a tightly constrained 200-line context window containing the vulnerable method and its verified taint propagation trace. The engine synthesizes a unified code diff rendered cleanly in Vue 3 via PatchDiffViewer.vue.

Simultaneously, the GitHub Checks integration attaches line-level annotations directly to the developer's Pull Request. If a confirmed vulnerability is detected, the check run concludes as failure, blocking the pull request from merging until the issue is resolved or an authorized Repository Owner or Admin executes an explicit override.
