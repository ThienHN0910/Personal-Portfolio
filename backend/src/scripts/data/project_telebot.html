Dev Assistant Bot — Telegram Server Automation & Multi-Target Deployment Suite

Dev Assistant Bot is an interactive DevOps assistant, multi-target cloud deployment orchestrator, and real-time monitoring suite engineered with Node.js, Telegraf, and Vue 3. Tailored specifically for memory-constrained cloud environments (Google Cloud Platform 1 vCPU / 1 GB RAM e2-micro/f1-micro), the platform orchestrates remote hardware telemetry, automated Nginx virtual hosting, multi-cloud deployments across VPS, Vercel, and Render, dynamic Cloudflare DNS routing (*.thienhn.io.vn), and a centralized Vue 3 administrative dashboard secured by Google OAuth 2.0.

ARCHITECTURAL HIGHLIGHTS 0 MB RAM OVERHEAD CLOUDFLARE DNS AUTOMATION MULTI-TARGET ORCHESTRATION
  • OOM-Safe Log Streaming: Streams PM2 error logs using an optimized tail -n 20 OS pipe, consuming 0 MB Node.js runtime memory and eliminating Out-Of-Memory (OOM) kernel terminations on 1GB VPS hosts.
  • Intelligent Multi-Target Deployments: Discovers ZIP archives or analyzes public GitHub repositories via Smart Repo Inspector, classifying architectures into Pure Static (VPS Nginx), Frontend SPA (Vercel Cloud), Backend API (Render/VPS), or Monorepo (Parallel Vercel + Render).
  • Automated Cloudflare DNS Routing: Dynamically provisions and binds subdomains (e.g., <project>.thienhn.io.vn) using Cloudflare API v4 (Type A for VPS, Type CNAME for Vercel/Render) and automatically reclaims DNS records upon project deletion.
  • Central Web Dashboard (Vue 3 + Google OAuth 2.0): Visualizes real-time CPU, RAM, Disk, and PM2 health telemetry, manages active deployments across all platforms, and enforces single-email Google OAuth verification (hnt.vn.vn@gmail.com).
  • In-Situ TTFB & Remote PageSpeed Auditing: Dissects network latency breakdowns via native curl -w (DNS, TCP, TTFB, Total) and retrieves Lighthouse Mobile scores remotely via Google PageSpeed Insights API with zero local CPU/RAM footprint.
  • Strict 200MB RAM Ceiling & Whitelist Security: Enforces --max-memory-restart 200M daemon limits, Telegram ID whitelist verification, and restricted shell alias execution.

🖥️ Module 1: Host Health Suite & Hardware Telemetry

The bot provides a rapid hardware telemetry monitoring suite responding within milliseconds over Telegram, enabling developers to monitor infrastructure health and diagnose bottlenecks without initiating SSH sessions:

  • /status: Real-time telemetry report detailing CPU load (%), physical RAM utilization (used / total), SWAP allocation, and available root disk storage (/).
  • /ps: Queries the Top 5 processes consuming the highest RAM and CPU percentages for rapid bottleneck diagnosis.
  • /uptime & /ip: Inspects cumulative host uptime, last boot timestamp, and active public IPv4 address.
  • /logs: Inspects the last 20 lines of PM2 error logs safely via OS pipes without buffering large log files into Node.js runtime memory.
  • /cleancache: Flushes OS file system caches safely and resets PM2 operational logs (pm2 flush).
  • /restart: Triggers a graceful PM2 process restart with pre-execution message acknowledgment and memory limits.
  • /notes: Appends critical runtime commands, configurations, or quick thoughts directly into a local persistent notes.txt storage.

🚨 Module 2: Proactive Threshold Watchdog

To prevent server freezing caused by memory exhaustion or storage overflow, a Background Watchdog Worker runs every 5 minutes:

  • Dispatches priority emergency alerts directly to Telegram when RAM > 85% or Root Disk > 90%.
  • Implements a 30-minute notification cooldown to prevent alert flooding during prolonged high-load operations.

🌐 Module 4: Cloudflare DNS Subdomain Automation

Eliminating manual DNS dashboard configuration, the bot communicates directly with the Cloudflare API v4:

  • Automatic Record Provisioning: Creates subdomains formatted as <project>.thienhn.io.vn. For VPS-hosted sandboxes, it binds a Type A record to the detected public IPv4. For Vercel or Render deployments, it creates a Type CNAME record targeting cname.vercel-dns.com or Render service domains.
  • Zero-Orphan DNS Reclamation: Executing /web_remove <name> or clicking Undeploy in the Dashboard cleans up the Nginx virtual host, terminates the PM2 process, and automatically invokes the Cloudflare API to delete the corresponding DNS record.

📊 Module 5: Central Web Dashboard (Vue 3 + Google OAuth 2.0)

In addition to Telegram chat commands, the suite features a dedicated Single Page Application dashboard served at bot.thienhn.io.vn built with Vue 3, Tailwind CSS, and Google Identity Services:

  • Real-time Telemetry Dashboard: Visualizes CPU utilization, RAM usage gauges, disk consumption, and host uptime (131+ days continuous operation).
  • Deployment Manager: Displays all active services with platform indicators (VPS, Vercel, Render), live HTTPS hyperlinks, Cloudflare DNS mapping types, and one-click removal buttons.
  • GitHub Repository Deploy Modal: Analyzes public repositories in real time, provides architectural recommendations, and permits custom subdomain customization.
  • Identity Whitelist Gate: Enforces Google OAuth 2.0 verification where only the administrator's authenticated email (hnt.vn.vn@gmail.com) receives stateless JWT session tokens.

⚡ Module 6: In-Situ TTFB Benchmarking & Remote PageSpeed Audits (/perf)

Auditing web performance directly on low-spec hardware without CPU choking is achieved via two zero-overhead paradigms:

  • In-Situ TTFB Breakdown via curl -w (0 MB RAM): Deconstructs network timings with microsecond precision: DNS Resolution, TCP Handshake, Time To First Byte (TTFB), and Total Duration.
  • Google PageSpeed Insights API Integration: Queries Google's remote API to calculate Lighthouse Mobile scores (FCP, LCP, TBT, CLS) without executing memory-heavy Chromium headless instances on the host.

🔒 Module 7: Zero-Leakage Security, 200MB RAM Ceiling & Autonomous Upgrades

  • 200MB RAM Hard Ceiling: Configured with --max-memory-restart 200M in PM2, ensuring the bot runtime never creeps past memory thresholds.
  • Multi-Factor Authorization: Single-user Telegram ID whitelist on the bot interface, coupled with Google OAuth email verification on the web dashboard.
  • Restricted Shell Execution: The /sh command executes only pre-validated aliases registered in config/whitelist.js, preventing arbitrary code injection.
  • Self-Healing Upgrades (/update): Pulls updates from GitHub, audits dependencies, validates syntax (npm run check:syntax), runs unit test suites, and executes a clean PM2 process reload autonomously.
